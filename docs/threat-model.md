# Threat model (≥ 6 threats, each mapped to an implemented control)

| # | Threat | Category (identity / data / API / cloud config) | Affected part | Implemented control | Test ID |
|---|---|---|---|---|---|
| R1 | A reviewer reads or changes an application another reviewer claimed by guessing its id | API | review-service | Every `/{applicationId}` route checks the claimer from the token; someone else's claim returns 404 (not 403) so ids can't be probed; ids must match a fixed pattern | T-REV-10 |
| R2 | Two reviewers claim the same application at the same moment, or a released or expired claim is still scored | API | review-service, Applications | Each status change is one conditional `UpdateItem` (DynamoDB), so only one request wins; scoring also requires the claim to still be held | T-REV-08, T-REV-13 |
| R3 | A reviewer tampers with the result: sends their own total, extra criteria, out-of-range scores, or overwrites a submitted review | data | review-service, Reviews | Scores validated against the scholarship's rubric (whole numbers 0-10, no extra keys); total calculated on the server; reviews written once (`attribute_not_exists`); the role has no Update or Delete on `Reviews` (IAM) | T-REV-11, T-REV-12, T-REV-13 |
| R4 | A student's PDF (personal data) is reached by someone who should not see it | data | review-service, S3 `scholarship-documents` | Private bucket with Block Public Access (S3); 5 minute presigned link only for the claimer while under review; every link written to `AuditLog` as `pdf_download`; link never logged | T-REV-19 |
| R5 | Script in an essay runs in the reviewer's browser (stored XSS) and steals the token | API | frontend/reviewer | Essays shown with `textContent` only; CSP meta tag allows only our own scripts; API responses have CSP `default-src 'none'` and `nosniff` | T-REV-23, T-REV-24 |
| R6 | Password guessing across many accounts goes unnoticed | identity | auth-service logs | CloudWatch metric filter `login-failed` and alarm `login-failed-spike` (more than 20 in 5 minutes), on top of the per email + IP backoff | T-AUT-30 |
| R7 | Abandoned claims block applications from ever being reviewed | cloud config | review-service | EventBridge Scheduler runs `release-expired-claims` hourly and returns claims older than 48 h to the queue (`claim_expired` in AuditLog) | T-REV-20 |
