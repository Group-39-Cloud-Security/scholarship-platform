# Threat model (≥ 6 threats, each mapped to an implemented control)

| # | Threat | Category (identity / data / API / cloud config) | Affected part | Implemented control | Test ID |
|---|---|---|---|---|---|
| R1 | A reviewer guesses the id of an application someone else claimed and tries to open or change it | API | review-service | Every route with an id checks that the reviewer in the token is the one who claimed it. If not it returns 404 instead of 403, so the reviewer can't tell if the id exists. Ids must also match a regex. | T-REV-10 |
| R2 | Two reviewers claim the same application at the same time, or someone scores a claim that was already released or expired | API | review-service, Applications | Each status change is one conditional UpdateItem in DynamoDB, so only one request can win. Scoring also checks that the claim is still theirs. | T-REV-08, T-REV-13 |
| R3 | A reviewer changes the result, for example sends their own total, extra criteria, scores out of range, or overwrites a review | data | review-service, Reviews | Scores are checked against the scholarship's rubric (whole numbers 0-10, no extra criteria) and the server calculates the total. Reviews are written once (`attribute_not_exists`) and the IAM role can't update or delete them. | T-REV-11, T-REV-12, T-REV-13 |
| R4 | Someone who shouldn't see it opens a student's PDF | data | review-service, S3 `scholarship-documents` | The bucket is private (Block Public Access). Only the reviewer who claimed the application gets a link, it lasts 5 minutes and it's saved in AuditLog as pdf_download. The link is never logged. | T-REV-19 |
| R5 | A script inside an essay runs in the reviewer's browser (stored XSS) and steals the token | API | frontend/reviewer | Essays are shown with `textContent` only and the CSP meta tag only allows our own scripts. API responses have CSP `default-src 'none'` and nosniff. | T-REV-23, T-REV-24 |
| R6 | Someone tries passwords on many accounts and nobody notices | identity | auth-service logs | CloudWatch metric filter `login-failed` and alarm `login-failed-spike` (more than 20 in 5 minutes), together with the email + IP backoff in auth-service | T-AUT-30 |
| R7 | Reviewers claim applications and forget about them, so they never get reviewed | cloud config | review-service | `release-expired-claims` runs every hour from EventBridge Scheduler and puts claims older than 48 hours back in the queue (saved as claim_expired in AuditLog) | T-REV-20 |
